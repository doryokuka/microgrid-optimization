# 微网购电策略：滚动预测与多阶段优化

本项目研究如何在负荷、光伏发电及电价信息逐步更新的条件下，安排微网购电和储能运行，降低总购电成本及预测误差带来的紧急购电支出。

项目来自数学建模竞赛团队的共同工作，核心路线为 **LightGBM 滚动预测 → 历史残差 Q80 修正 → 滚动优化 → 实际运行结算与核验**。本仓库提供核心源码和方法说明；原始赛事数据及部分运行输入未公开，因此当前版本不能直接复现全部论文实验。

## 研究问题

预测准确并不必然意味着购电成本最低：低估净负荷可能触发高价紧急购电，过度采购又会增加普通购电支出。储能还会将当前决策的影响传递到下一时段和下一天。

我们围绕四个逐步扩展的问题建立模型：

| 问题 | 信息条件 | 主要方法 |
| --- | --- | --- |
| 第一问 | 日内负荷、光伏及电价已知 | 连续线性规划，联合安排购电与储能 |
| 第二问 | 每日使用此前历史数据预测负荷与光伏 | LightGBM、Q80 残差修正、48 小时规划与 24 小时执行 |
| 第三问 | 每日 0、6、12、18 点更新信息 | 四时点滚动基准及三分支两阶段前瞻，每次执行前 6 小时 |
| 第四问 | 电价也需要预测 | 引入滚动电价预测，并按实际交付电价结算 |

## 方法概述

**滚动预测。** 分别预测负荷和光伏发电，使用时段、日历、历史滞后值及滚动统计特征。第二问的训练输入限于发布预测前的历史数据；次日预测通过当日已发布预测递推构造。历史不足时使用朴素预测冷启动。

**Q80 风险修正。** 在净负荷点预测上加入已观测历史预测残差的 80% 分位数，以缓解低估净负荷造成的紧急购电风险。Q80 是残差分位数修正，不表示 80% 的供电可靠性保证。

**滚动优化。** 第二问规划未来 48 小时，仅执行前 24 小时，再用新信息重新规划，储能状态跨日连续。第三问在 0、6、12 点考虑下一次信息发布的三分支两阶段前瞻，18 点使用 Q80 滚动基准。

**结算与核验。** 程序包含能量平衡、储能状态递推、功率与容量边界、费用分解及求解上下界/gap 检查。第三、四问的调整费相对当日零点原合同计算，最终费用按实际执行结果结算。

时间步长为 10 分钟；输入功率为 kW，调度电量及储能状态为 kWh。储能充放电效率均为 0.9，容量范围为 1200–10800 kWh，充放电功率上限为 5000 kW。

## 主要结果

下列结果来自团队论文及支撑材料中的实验记录。第二至第四问的正式统计期为 **2025-02-01 至 2025-12-31，共 334 天**；一月用于启动。

| 实验 | 比较基准与结果 |
| --- | --- |
| 第一问：确定性调度 | 单日购电费 35,126.85 元，相对无储能方案下降 26.90% |
| 第二问：净负荷预测 | LightGBM 的 MAE 为 246.46 kW、RMSE 为 361.97 kW；相对前一周同刻值基准分别下降 24.81% 和 25.59% |
| 第二问：Q80 调度 | 正式期总费用 13,687,668.51 元；相对使用相同 LightGBM 点预测、但不加 Q80 修正的 point 基准，总费用下降 8.30%，紧急购电费下降 78.62% |
| 第三问：两阶段前瞻 | 正式期总费用 13,393,736.62 元；相对四时点 Q80 滚动基准的 13,455,875.53 元，节约 62,138.91 元，约 0.4618% |
| 第四问：电价预测下的滚动调度 | 按真实电价结算，4-2 与 4-3 的总费用分别为 14,359,725.62 元和 14,073,722.63 元，后者下降约 1.99% |

这些结果对应特定数据和模型设定。不同问题的信息条件、合同机制和电价条件不同，不能直接用它们的总费用比较某个单独方法的效果。第三问前瞻方案降低了总费用，但紧急购电费略高于四时点基准，并非所有指标都改善。

## 环境与运行方式

原材料建议 Python 3.12、64 位环境。各问使用各自的 `requirements.txt`；`requirements-tested.txt` 记录原材料所述环境版本，不代表本公开版已在干净环境完成安装验证。

### 先准备运行输入

当前公开源码不包含原始数据、赛事模板、冻结预测或参考轨迹。完整依赖见 [数据与复现说明](docs/data-and-reproduction.md)。

- 第一问需要 `src/附件/附件1.xlsx` 和 `src/附件/附件5/result1.xlsx`。
- 第二问需要其 `data/` 中的原附件、`calendar.npz`、`sha256.json` 及哈希清单列出的全部文件。`--retrain` 会重新训练预测，但仍执行完整输入校验；目前清单还包含冻结预测和提交模板。
- 第三问需要公共附件、`centers.npz`、`startup.npz`，现有运行结束后的审计还需要 `baseline_reference.npz` 和 `reference.npz`。
- 第四问的源码仍引用同层 `第二问最终版_Q80`，与当前 `第二问` 目录名不一致；在修复路径并恢复输入前，第四问入口不可直接运行。

以下命令适用于**已合法取得所需输入并按原布局恢复文件**的环境；当前源码包本身不能完成这些计算。

### 第一问

```bash
cd src/第一问
python -m pip install -r requirements.txt
python -B solve_q1.py --output outputs
```

### 第二问

```bash
cd src/第二问
python -m pip install -r requirements.txt

# 重新训练预测，计算一月启动期及两个正式日
python -B run.py --retrain --smoke --output smoke_outputs

# 完整 Q80 计算；使用新的空输出目录
python -B run.py --retrain --output retrained_outputs

# 对已完成计算汇总指标并核验
python -B analyze.py --output retrained_outputs
```

不加 `--retrain` 时，默认使用冻结发布预测。比较全部五种方法可使用 `--all-models`；仅运行默认 Q80 不会自动生成 point 基准的对比结果。完整计算可能耗时较长，短跑结果不能替代正式期结果。

### 第三问

```bash
cd src/第三问
python -m pip install -r requirements.txt
python -B run.py run --days 1 --output outputs/one_day
```

该入口使用冻结预测中心重新构造风险修正与信息分支，不会重新训练完整历史预测流程。`check-reference` 与 `export-json` 读取既有参考轨迹，不能视为重新优化。

第四问及输入恢复细节见数据与复现说明。当前尚无公开合成数据演示入口。
