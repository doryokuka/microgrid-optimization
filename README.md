# Microgrid Forecasting and Optimization

基于 LightGBM 滚动预测、Q80 风险修正与多阶段优化的微网购电策略研究。

本项目由数学建模竞赛团队共同完成。本仓库展示团队的建模、计算与验证方法，不代表仓库维护者独立完成全部工作。个人分工将在团队确认后补充；当前不对成员贡献作未经核实的归属。

## 问题与方法

研究如何在负荷、光伏与电价信息逐步到达时安排购电和储能运行，降低普通购电、合同调整及紧急购电的总费用。

- 第一问：已知日内数据下的连续线性规划；求解后检查充放电互斥，并核验原始与对偶目标。
- 第二问：LightGBM 因果滚动预测，历史预测残差的 80% 分位数修正，48 小时规划、24 小时执行，SOC 跨日连续。
- 第三问：0/6/12 点考虑下一次信息发布的三分支两阶段前瞻，18 点使用 Q80 滚动基准，每次执行前六小时。
- 第四问：加入滚动电价预测，在实际交付电价下结算并比较策略。

十分钟电量使用 kWh，输入功率使用 kW；SOC 使用 kWh。充放电效率均为 0.9，SOC 范围 1200–10800 kWh，充放电功率上限 5000 kW。第三问按实际交付量计普通费用，并相对当日零点原合同计调整费用：`p*q + 0.5*p*abs(q-q0) + 5*p*e`。

## 代码与核验

`src/第一问/solve_q1.py` 是日内 LP 入口；`src/第二问/q2/` 包含预测、风险修正、优化、储能结算及审计流程；`src/第三问/model/` 包含两阶段规划与独立核验；`src/第四问/代码/` 包含电价预测与适配模型。

核验范围包括能量平衡、SOC 递推与连续性、充放电功率边界、计费分解、情景的因果信息边界，以及求解上下界和 gap。核验通过不自动等于预测无泄漏、统计泛化良好或全局最优。

## 环境与复现边界

建议 Python 3.12。各问依赖见其子目录 requirements 文件。`requirements-tested.txt` 是原材料记录的版本，并非本仓库新验证的锁定环境；公开前需在干净环境确认可安装性与兼容性。

此版本是源码展示草稿，未包含赛事附件、提交模板、冻结预测中心、启动轨迹、年度参考结果及输入哈希清单，因此不能直接一键复现论文。未修改原代码逻辑，也未用虚构数据冒充原实验。

取得合法输入并恢复原目录、数据和校验文件后，可按以下原入口运行：

```bash
cd src/第一问
python -m pip install -r requirements.txt
python -B solve_q1.py --output outputs
```

```bash
cd src/第二问
python -m pip install -r requirements.txt
python -B run.py --retrain --smoke --output smoke_outputs
python -B run.py --retrain --output retrained_outputs
python -B analyze.py --output retrained_outputs
```

第二问即使使用 `--retrain`，仍需 calendar.npz、原附件以及 sha256.json 中列出的文件，详见 docs/data-and-reproduction.md。默认入口使用冻结预测缓存。

```bash
cd src/第三问
python -m pip install -r requirements.txt
python -B run.py run --days 1 --output outputs/one_day
```

第三问以冻结发布预测中心和共同启动轨迹为输入，重新构造因果 Q80 与信息分支，不重新训练所有历史预测。现有 run 命令结束后的审计还读取基准参考轨迹。`check-reference` 和 `export-json` 使用既有结果，不能视为重新优化。

第四问源码当前引用同层 `第二问最终版_Q80`，实际归档目录为 `第二问`。运行前需恢复源码所要求的目录布局；本草稿未替用户修改路径或算法。
